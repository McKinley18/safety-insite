# V5-C03 Sufficiency Reason Classification

Date: 2026-08-16

## Method

`EvidenceSufficiencyService.evaluateEvidenceSufficiency()` scores 9 dimensions (`factScores`) and derives a single `sufficiencyLevel` (`sufficient` / `partially_sufficient` / `weak` / `insufficient`) via `levelFromScore()`: `sufficient` requires `overallScore >= 0.78` and not "critically weak" (`observationClarity`, `exposureClarity`, or `mechanismClarity` all `>= 0.3`) and `<= 1` missing critical fact; `partially_sufficient` requires `>= 0.58` and not critically weak; `weak` requires `>= 0.35`; anything below is `insufficient`.

**Direct empirical probe** (`scratch_disconnect_probe.ts`, run against the live `EvidenceSufficiencyService` with the C02 shared facts as the 4th argument, text-only — i.e. the conservative floor, since the live orchestrator additionally populates `observationUnderstanding`/`causalRiskReasoning` from real structured services, which this standalone probe passed as `{}` and so understates real-request scores):

| Case | sufficiencyLevel | overallScore | Live `resultStage` today |
|---|---|---|---|
| "There is a problem with the equipment." (genuinely vague) | `insufficient` (0.29) | below every threshold | `final` / `mayFinalize: true` — **the proven disconnect** |
| "Something unsafe was noted near the equipment area." (ambiguous) | `insufficient` (0.29) | below every threshold | `final` / `mayFinalize: true` — **the proven disconnect** |
| "The machine guard is missing and the operator can reach the rotating shaft while the conveyor is running." (clearly actionable hazard) | `weak` (0.39) | below `partially_sufficient` | `final` / `mayFinalize: true` — **already correct, must not regress** |
| "Local exhaust ventilation is running but fumes remain..." (failed control, still actionable) | `weak` (0.39) | below `partially_sufficient` | `final` / `mayFinalize: true` — **already correct, must not regress** |

**Critical calibration finding:** the clearly-actionable "sufficient" case and the genuinely-vague "insufficient_vague" case are *both* below `partially_sufficient`, and the scorer's own `mechanismClarity` dimension is `0.15` (rock-bottom) for **every** case tested, including the clearly-sufficient one — because this standalone-probe path never received a populated `observationUnderstanding.mechanismCandidates`. This proves the single `sufficiencyLevel` enum (and any of its component dimensions in isolation) is **not** a safe blocking signal on its own — using `weak` or worse as a blocking threshold would have blocked the clearly-sufficient case, directly violating "do not make every unknown fact block finalization." Only the bottom tier, `insufficient`, cleanly separated the two vague cases (0.29) from the two substantive cases (0.39) in this probe, and per the capability audit's own §9 recommendation ("do not keep numeric confidence as the primary signal... reserve numeric scores strictly for internal ranking"), the categorical `insufficient` tier — not a hand-tuned numeric cutoff — is the only signal used for blocking in this phase.

## Reason inventory and classification

| Reason (drives `missingCriticalFacts` / low `factScores.*`) | Classification | Rationale |
|---|---|---|
| `sufficiencyLevel === 'insufficient'` (the aggregate bottom tier — observation, equipment, task, exposure, energy, control, mechanism, jurisdiction, and evidence-support are *simultaneously* weak) | **BLOCKING_DEFICIENCY** | This is the one condition the empirical probe shows reliably corresponds to "HazLenz could not identify what the hazard even is" (no equipment, no exposure, no mechanism, no energy signal) rather than merely one missing refinement. Presenting such an analysis as `final` is the exact "insufficiently supported analysis presented as final" failure mode this phase must close. |
| `jurisdictionClarity` low / "jurisdiction or site type" missing, in isolation | **NON_BLOCKING_CLARIFICATION** (already correctly excluded — see below) | Jurisdiction changes *which standard* applies, not *whether* a hazardous condition was observed. Already explicitly excluded from blocking by the protected file's own `isSafetyDecisive()` (`if (question.requiredFor === "jurisdiction") return false;`, line 614) — C03 preserves this, does not touch it, and does not let a low `jurisdictionClarity` score alone trigger the new gate. |
| `energyClarity`/`controlFailureClarity` low *when a specific hazard mechanism is otherwise identified* (e.g. "sufficient", "failed_control" cases — equipment/exposure clarity present) | **CONTEXT_DEPENDENT, resolved to non-blocking** | The empirical probe shows these can be low even for clearly-actionable hazards (a real hazard can be well-evidenced on equipment/exposure while energy-state or control-effectiveness detail is still being refined). Per the product rule ("a missing fact should block finalization only when its absence prevents a defensible safety decision"), this is not, by itself, sufficient to block — it is already correctly handled by the existing targeted-clarification-question mechanism (a specific, answerable question is raised; finalization proceeds because the underlying hazard is still defensible). C03 does not change this. |
| `taskClarity`/`mechanismClarity` low in isolation, hazard otherwise identified | **OPTIONAL_ENRICHMENT** | Improves narrative/corrective-action specificity but does not change whether a hazardous condition exists. Empirically low (`0.15`-`0.25`) even in the clearly-sufficient case in this probe's text-only path — treating it as blocking would fail the "sufficient" case in the required decision matrix. |
| `evidenceSupport` low (no photos/measurements/records referenced) | **OPTIONAL_ENRICHMENT** | Affects defensibility *strength*, not hazard identity; the product already treats every HazLenz output as advisory pending qualified human review regardless of this dimension (`advisoryGuardrails.requiresQualifiedReview: true` unconditionally). |
| `unresolvedContradictions.length > 0` (structured-observation contradiction, not from `EvidenceSufficiencyService` at all — from `safescope-v2.service.ts`'s own contradiction detection) | **BLOCKING_DEFICIENCY** — already implemented, untouched | This is "material ambiguity" (Phase 7's second matrix row: evidence supports materially different conclusions). Already correctly blocking via the existing, protected-file logic (`response.resultStage = unresolvedContradictions.length || ...`). C03 does not duplicate or touch this — it is out of `EvidenceSufficiencyService`'s scope entirely. |
| The 5-ID hardcoded `safetyDecisiveIds` allowlist (`machine-energy-state`, `machine-controls`, `electrical-damage-exposure`, `gap-conveyor-loto`, `gap-p4-roof-rib-ground-control`) plus the `couldChangeShutdown` / `confirm-*` generic rules | **DEFECTIVE_RULE (narrow scope, not a false positive)** | Not incorrect on its own terms, but a hardcoded ID allowlist can never generalize to hazard families outside those 5 IDs (exactly the audit's finding). C03 does not replace or widen this list (that would require editing the protected file) — it adds a second, independent, narrower gate (the `insufficient`-tier check above) that catches the specific failure mode the allowlist structurally cannot: an observation with *no* recognized hazard signal at all, regardless of which family it might belong to. |

## Answers to the task's explicit questions

- **Does missing jurisdiction prevent hazard recognition, or only standards refinement?** Only standards refinement — confirmed both empirically (probe) and architecturally (the protected file already excludes it from blocking).
- **Does unknown control effectiveness prevent a defensible hazard finding?** No, not by itself — the "failed_control" case (`controlFailureClarity: 0.2`, i.e. "unclear/unknown" by the scorer's own text-fallback heuristic, distinct from C02's `controlEffectiveness: present_but_ineffective` fact which *is* established) still has a defensible finding (ineffective control + persistent hazard signal) and correctly finalizes today.
- **Does an unresolved ambiguity change whether a hazard exists?** Yes, when it manifests as `unresolvedContradictions` (already blocking, untouched by C03) — but a merely-low sufficiency dimension is not the same as an unresolved contradiction and is not treated as one.
- **Does missing optional context merely improve corrective-action quality?** Yes for task/mechanism/evidence-support dimensions — classified `OPTIONAL_ENRICHMENT`.
- **Can the system safely produce a bounded finding while still asking a clarification?** Yes — this is the existing, preserved behavior for every case except the new `insufficient`-tier gate.
- **Is a supposedly missing fact actually UNKNOWN rather than ABSENT?** `EvidenceSufficiencyService`'s dimensions are inherently "how clearly is X established," i.e. genuinely `UNKNOWN`-flavored, not a claim that a condition is `ABSENT` — C03's gate never converts a low score into an invented `ABSENT` fact; it only ever withholds `final`/`mayFinalize` pending clarification.
- **Is the question relevant to one finding or the entire observation?** `EvidenceSufficiencyService` runs once per observation (not per decomposed hazard) today — see `V5_C03_DECISION_MATRIX.md` §multi-hazard for the finding-scope limitation this implies and how it is handled without fabricating false precision.
