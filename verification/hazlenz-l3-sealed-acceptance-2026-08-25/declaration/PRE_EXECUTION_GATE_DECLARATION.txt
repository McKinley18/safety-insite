6. FIELD DERIVATION -- DECLARED NOW, BEFORE ANY OBSERVATION IS OPENED
================================================================================
  The frozen scorer defines the GATES. It does not define how the shipped pipeline's output maps
  onto its input fields, because no acceptance harness existed at freeze time (HOLDOUT_FREEZE.txt
  s.13). Each mapping below is therefore DECLARED HERE, BEFORE EXECUTION, and derived from a
  frozen artifact that is named. NO MAPPING MAY BE CHANGED AFTER A RESULT IS SEEN.

  EXECUTION PATH -- the shipped, governed sequence, nothing rewritten:
      buildReasoningInput (2865ae91, MANDATORY per D-81)
        -> OllamaReasoningProvider.analyzeObservation  [L3_SYSTEM_PROMPT b8cc50fc,
             buildProposalSchema a522cf5a, buildUserPrompt -- all shipped, unmodified]
        -> the frozen anthropic-ollama-shim.js (76d3e039) -> api.anthropic.com, claude-sonnet-5
        -> bindProposal (shipped)
        -> validateReasoningProposal (942ac7cc)
        -> bindEvidenceSemantically (c1f9d29d)
      composed by the SHIPPED runValidatedReasoning (reasoning-runner.ts), which is the only
      place the four stages are composed and which carries the FROZEN retry ceiling of ONE.

  rowId
      the holdout row's frozen rowId. Verbatim.

  schemaValid
      TRUE iff the provider returned a structured proposal that parsed and bound, AND the
      validator raised no RETRYABLE_VALIDATION_REASONS code (SCHEMA_INVALID,
      CONTRACT_VERSION_MISMATCH -- validation-result.types.ts).
      FALSE on MALFORMED_OUTPUT, PROVIDER_TIMEOUT, PROVIDER_UNAVAILABLE, or a schema-shape code.

  retries
      attempts - 1, where `attempts` is the SHIPPED runner's own counter. The retry ceiling is
      ONE and it is the frozen policy of reasoning-runner.ts. NO NEW RETRY POLICY IS INVENTED.
      A retry occurs ONLY for: a RETRYABLE_PROVIDER_FAILURE (TIMEOUT, TRANSIENT_ERROR,
      MALFORMED_STRUCTURED_OUTPUT) or a validator state of RETRYABLE_MODEL_OUTPUT whose issues
      are ALL retryable. A SEMANTIC retry -- re-asking because an answer is undesirable -- is
      PROHIBITED and is not reachable in this code path.

  candidates
      the VALIDATED-tier hazards: validation.validated.hazards.
      WHY THIS TIER: D-58 fixes a two-tier vocabulary -- MODEL tier and VALIDATED tier -- and G1
      names the VALIDATED tier explicitly. The frozen precedent for that field is
      activate-l32j-shipped-corpus.ts (0b3b8d86) and score.js (7d748111), both of which read
      validation.validated.hazards.
      THE SEMANTIC-BINDER TIER IS ALSO RECORDED on every row (boundHazards, demotions, binder
      issue codes) so the two tiers are visible separately and NEVER merged (D-58). It is
      recorded, not scored, because D-84 names the VALIDATED tier.

  raisedClarification
      candidate-borne clarification OR a non-empty validated proposal-level unresolvedDecisions --
      i.e. `clarificationCarriedAnywhere`, the frozen field of activate-l32j (0b3b8d86) that
      score.js (7d748111) reads. A clarification counts wherever the pipeline carries it.

  assertedState
      'ACTIVE' iff any VALIDATED-tier hazard has conditionState === 'ACTIVE'; otherwise the
      state string of the first validated hazard, or null when there is none. The frozen scorer
      tests only `=== 'ACTIVE'`. This is `validatedAssertsActive` of 0b3b8d86 / 7d748111.

  nonRetryableValidationReasons
      the validator's issue codes intersected with NON_RETRYABLE_VALIDATION_REASONS
      (validation-result.types.ts, ten codes). Reported, never suppressed (D-D.3).

  safetyConsequentialRejection
      TRUE iff the validator state is NOT 'VALID' AND the row's frozen truth owed a hazard.
      L3-2p (analysis/adjudicate.js) froze the severity split: "A rejection is SAFETY_CONSEQUENTIAL
      exactly when the row's ground truth owed a hazard, because the runner discards the whole
      proposal on any deciding issue, so the owed hazard is not delivered."
      OWED A HAZARD, on this holdout, using DECLARED truth only and inferring nothing from text,
      pole or heuristic:
          expect.conditionState === 'ACTIVE'     (the holdout's exact analogue of expectActive)
       OR expect.highConsequence === true        (the holdout's own declaration that the row owes
                                                  a validated finding -- it is G1's denominator)
      This is the UNION of the two declared truths that assert an owed hazard. It is the stricter
      reading, which is the conservative direction for a hard-zero safety gate.

  decisionBoundaryCodes
      all validator issue codes. The frozen scorer applies its own filter to the two G8 codes.
