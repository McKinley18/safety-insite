produced "STORAGE_LOCAL_ROOT is required for local test storage."  §262 requires that a
changed failure mechanism be investigated rather than reclassified, so it was.

  - src/storage/storage.service.ts:34 selects the provider as

    so the branch taken is decided by the SERVER PROCESS's NODE_ENV, not by any §262 code.
  - The first §262 run booted the server with NODE_ENV=test, which selects local_test.
    §261 booted it without, which selects s3. That is the entire difference.
  - Re-running the suite against a server booted the way §261 booted it (port 4233,
    NODE_ENV not set to test) reproduces §261's cause exactly:
        [ExceptionsHandler] STORAGE_S3_BUCKET is required.
    The suite fails at POST /inspections/:id/reports with 500, as it did in §261.
  - STORAGE_S3_BUCKET occurs 0 times in backend/.env; no STORAGE_* variable is set.
  - §262 changed 0 files under src/storage and 0 files under src/reports
    (git status --porcelain over both paths returns 0 lines).
  - §262 explicitly prohibits configuring object storage to make this suite green, and
    STORAGE_LOCAL_ROOT was therefore NOT set either: setting it would be configuring
    object storage to turn an unrelated suite green, which is the prohibited act
