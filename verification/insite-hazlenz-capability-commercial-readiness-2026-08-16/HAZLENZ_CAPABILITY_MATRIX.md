## Root cause (confirmed at the source, not inferred from behavior)

The headline `classification`/`family`/`confidence` triple is produced by `backend/src/safescope-v2/engine/deterministic-classifier.ts`, a pure keyword-weighted scorer (`score += 3` tier-1 keyword, `+2` tier-2, `+1` tier-3; `confidence = 0.92` if `score >= 6`, `0.74` if `score >= 3`, else lower). The file contains **zero** occurrences of "negat" — there is no negation handling at this layer at all. Every FAIL row's `explanation` field confirms this in the product's own words:

- negation → `"HazLenz AI matched weighted Electrical signals."`
- safe-state → `"HazLenz AI matched weighted Fall Protection signals."`
- effective-control → `"HazLenz AI matched weighted Machine Guarding signals."`

Negation-aware logic **does exist** in the codebase (`backend/src/safescope-v2/reasoning-orchestrator/negation-context.util.ts`, referenced from `evidence/shared-evidence-facts.ts`, `verification-evidence/verification-evidence.service.ts`, `brain/scenario-disambiguation/scenario-disambiguation.service.ts`, `multi-hazard-decomposition/multi-hazard-decomposition.service.ts`, `standards-intelligence/standards-intelligence.service.ts`). It correctly drives `conditionState`/downstream fact extraction in some paths (e.g. `historicalHazards`, `PLANNED_FUTURE`), but it does not gate or override the primary keyword-weighted classifier's headline label/confidence on a raw free-text observation. The net effect: a user pastes a **completely clean, negated** observation and gets back a specific hazard family at 70-93% "high confidence" with no visual signal that anything is wrong short of opening the disposition metadata (`mayFinalize: false`) that isn't the first thing shown.

## Verdict for capability claims

- "Identifies hazards from written observations" — **PROVEN** for genuinely positive observations (single-hazard-fall, temporal cases, ambiguity case all behaved correctly and appropriately calibrated confidence to evidence strength).
- "Understands negation / won't invent a hazard from a clean observation" — **OVERSTATED** as currently implemented. This is a live, reproducible defect, not a hypothetical: 3 of 3 negation/effective-control probes in this session produced a false positive hazard classification at medium-to-high confidence.
- "Distinguishes control present from control effective" — **OVERSTATED**. The effective-control case scored *higher* confidence (0.93) than the failed-control case (0.82) for the identical underlying hazard family, which is inverted from what sound reasoning should produce.
- Every result is architecturally advisory-only and gated behind mandatory human review before any violation is finalized — this is real, verified, and is the correct mitigating claim to make in marketing ("HazLenz surfaces candidates for a qualified reviewer to confirm — it does not finalize compliance determinations on its own"), rather than claiming reliable hazard/no-hazard discrimination.
